# CODING_RULES.md (コーディング規約)

本プロジェクトにおける設計・コーディングの規約と品質基準です。
コードを記述・変更・レビューする際は、必ず本規約を遵守してください。

本規約は、**本プロジェクト固有の設計方針・アーキテクチャ規約** と、**Haskell 言語全般のコーディングルール** の 2 つに分割して管理されています。

## 基本原則サマリ

1. **ドメインの純粋性と型安全性**:
   - コアロジック (`src/common/`) は外部フレームワークや IO 副作用を持たない純粋関数とし、副作用は端点（インフラ層）に局所化する。
   - プリミティブを裸で引き回さず、`newtype` や型レベル検証 (`DataKinds`, `TypeFamilies`) を活用して不正な状態をコンパイル時に排除する。
   - テストコードに頼らずに型で保証できるものは積極的に型で保証する（ただし可読性を損なう過度な複雑化は避け、可読性を優先する）。
2. **パス操作における `OsPath` の優先**:
   - 文字列としての `FilePath` (`String`) を避け、エンコーディング安全な `OsPath` 系 API を標準とする。
3. **警告ゼロの義務化 (`-Wall -Werror`)**:
   - 自プロジェクトのパッケージは `-Wall -Werror` (警告をエラーとして扱う) でビルドされる。
   - 一切のコンパイラ警告を残してはならない。
4. **仕様・テスト・手順書の同期**:
   - 自動テスト (`scripts/test.sh`) を必ず伴うこと。
   - UI 操作やオフライン同期等の手動確認事項は [docs/MANUAL_TESTS.md](MANUAL_TESTS.md) に完全な手順として記録・更新する。
   - Web API を変更した場合は [docs/api/openapi.yaml](api/openapi.yaml) を同期更新する。
