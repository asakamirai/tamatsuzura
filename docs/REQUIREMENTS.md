# REQUIREMENTS.md — 要件定義

本ドキュメントは、本エディタシステムにおけるコア要件と動作制約を定義します。
※ 本要件は、M0 Phase 0（要件定義の確定）でユーザーにより最終調整される予定のベースラインです。

---

## 1. プロダクト概要

ブラウザ上で軽快に動作し、高い実用性と拡張性、堅牢な差分管理を備えたテキストエディタ。

---

## 2. 機能要件

### 基本機能・エディタ性能
- **実用的なテキスト編集**:
  - 実験的トイプログラムではなく、日常の文書作成・編集に耐えうる軽快で実用的なテキストエディタ機能。
  - 一般的なショートカットキー、検索・置換、複数行編集などをサポート。
- **サーバ保存と永続化**:
  - エディタ内で作成・編集した文書をサーバ上に保存・取得できること。
- **認証とユーザ管理**:
  - 最低限のユーザー認証 (登録・ログイン・ログアウト) と所有者ごとの文書分離。
  - 初期段階では最小限の構成とし、将来の拡張に対応できる設計とすること。

### 特殊機能・コア価値
- **Haskell による拡張機構**:
  - Emacs における Lisp のように、Haskell を用いてエディタ機能のカスタマイズやコマンド拡張が可能であること。
  - 最終的にクライアント (ブラウザ) 上で動作させるため、Haskell から JavaScript / WebAssembly にコンパイルされたモジュールをロード・実行できるアーキテクチャを備える。
- **高度な差分管理 (リビジョン管理)**:
  - 文書の更新履歴を差分 (diff) として追跡・管理できること。
  - 過去のリビジョンの閲覧や復元、リビジョン間の比較が可能であること。
  - 将来的に柔軟なパッチベースのマージや競合解決への拡張を視野に入れる。

---

## 3. 非機能要件・動作環境

### サーバ環境
- **軽量・ポータブルな実行**:
  - C言語の CGI が動作する環境、またはスタンドアロンの HTTP サーバ (Warp 等) 上で動作可能であること。
  - サーバ側言語としても可能な限り Haskell を採用する。
- **データストレージ**:
  - データの保存は SQLite などの組み込み DB またはファイルシステムで行う。

### クライアント環境
- **クロスプラットフォーム対応**:
  - スマートフォンおよび PC のメジャーなモダンブラウザ (Chromium 系、Firefox 等) で利用可能であること。
  - ※ Apple 系の制限の多いブラウザ (Safari 等) については制限事項としての対応を許容する。
- **オフライン動作と PWA**:
  - オフライン時でも文書の作成・編集が可能であること。
  - オンライン復帰時にサーバ側と安全に同期できること。
  - PWA (Progressive Web App) としてインストール可能であることが望ましい。
