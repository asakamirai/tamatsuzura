# REQUIREMENTS.md — 要件定義

本ドキュメントは、TamaTsuzura における確定済みのプロダクト要件・機能要件・非機能要件・スコープ境界を定義します。

---

## 1. プロダクト概要と想定利用形態

- **プロダクト概要**: スマートフォンおよび PC のブラウザ上で軽快に動作し、高い実用性・Haskell による拡張性・堅牢な差分管理を備えたテキストエディタ。
- **想定利用形態**: 個人〜少人数によるセルフホスト運用（レンタルサーバの CGI 環境や小規模サーバ等）。
- **主な対象文書**: Markdown およびプレーンテキストによる日常的な執筆・メモ・原稿作成。
- **体験の優先軸**: **スマートフォンでの編集・閲覧体験を主軸として優先（モバイルファースト）** しつつ、PC ブラウザでもキーボードショートカット等を活用して快適に執筆できること。

---

## 2. 機能要件

### 2-1. エディタ機能・文書整理
- **実用的なテキスト編集**:
  - 実験的トイプログラムではなく、日常の文書作成・編集に耐えうる軽快で実用的な編集体験を提供する。
  - エディタコアには CodeMirror 6 相当を採用し、Undo/Redo、検索・置換、複数行編集、主要キーボードショートカット、およびスマートフォン向けタッチ操作・ソフトキーボード環境での快適な入力をサポートする。
- **Markdown 対応と文書整理**:
  - Markdown プレビュー表示を提供する。
  - 文書一覧の検索・フィルタおよび整理機能（タグまたはフォルダ/階層等）を備える。

### 2-2. 保存モデル・論理削除・入出力
- **明示的保存とドラフト自動退避**:
  - **明示的な保存操作（`Ctrl+S` / Save ボタン）によってリビジョンを確定** し、サーバへ永続化する。
  - 編集中の未保存ドラフトはブラウザ側（IndexedDB）に自動退避し、タブ終了・誤操作・オフライン遷移時でも編集内容が失われないようにする。
- **論理削除（ゴミ箱）**:
  - 文書削除時はゴミ箱へ移動する論理削除を基本とし、ゴミ箱からの復元および完全削除を可能とする。
- **エクスポート・インポート**:
  - Markdown / プレーンテキスト形式での文書エクスポートおよびインポートに対応する。

### 2-3. 認証・ユーザ管理
- **初期スコープ（M3）**:
  - ブラウザからのユーザー新規登録（Sign up）・ログイン・ログアウト、および所有者ごとの文書分離を提供する。
  - CGI 環境と完全互換な **SQLite 永続化 Cookie セッション**（インメモリ状態に依存しないステートレス認証）を採用する。
- **将来の拡張余地（[backlog.md](./project/backlog.md) 管理）**:
  - セルフホスト運用時のクローズド化に向け、新規登録の無効化フラグ・招待制・管理者/CLI によるユーザー作成など、登録制限を設定で切り替えられる設計余地を維持する。

### 2-4. Haskell 拡張機構
- **コアコンセプト**: Emacs における Lisp のように、Haskell を用いてエディタのコマンドやテキスト変換・編集挙動を型安全に拡張可能とする。
- **初期スコープ（M5）**:
  - 公開インターフェース（`src/extension-api/`）を介した **同梱・ビルド時組み込みの Haskell 拡張群** をクライアント側で有効化・設定・実行できるアーキテクチャを構築する。
- **将来課題（[backlog.md](./project/backlog.md) 管理）**:
  - 第三者またはユーザーが外部ビルドした `.wasm` 拡張モジュールの動的ロードおよび Web Worker 分離実行（初期段階から `src/extension-api/` の疎結合境界を維持して将来移行に備える）。

### 2-5. 高度な差分管理（リビジョン管理）
- **リビジョン履歴（M4）**:
  - 明示的保存ごとに更新履歴を unified diff ベースの追記型リビジョンとして記録・管理する。
  - 過去リビジョンの閲覧および任意リビジョンへの復元（ロールバック）を可能とする。
- **リビジョン比較とマージ（M7）**:
  - 任意の 2 リビジョン間の差分比較表示を提供する。
  - オフライン編集や同時編集による競合発生時、3-way マージおよび手動競合解決 UI を提供する。

## 3. 非機能要件・動作環境

### 3-1. サーバ環境（CGI 最優先・Warp 両対応）
- **実行形態（M1 必須要件）**:
  - **レンタルサーバ等の C 言語 CGI が動作する環境での動作を最優先** とし、**M1 の段階から CGI（`wai-extra` の `Network.Wai.Handler.CGI`）およびスタンドアロン HTTP サーバ（`warp`）の両対応を必須完了条件** とする。
  - WAI 抽象によりアプリケーション本体を共通化し、エントリポイントのみを CGI 用・Warp 用で分離する。
- **ステートレス性と軽量起動**:
  - CGI の 1 リクエスト 1 プロセス起動モデルを前提とし、セッション・一時状態を含めメモリ内状態に依存しない設計とする。
  - 依存パッケージを適切に選定し、CGI 実行時のコールドスタート負荷を抑える。
- **データストレージ**:
  - SQLite を標準採用し、CGI 並行リクエストに耐える設定（WAL モード、`busy_timeout` 等）を初期から組み込む。
- **静的アセット配信**:
  - CGI 本番環境では HTML / JS / CSS / Wasm の静的アセットを Web サーバから直接配信し、API リクエストのみを CGI バイナリへルーティングする（Warp 開発時は Warp 側からも静的配信可能とする）。

### 3-2. クライアント環境（Haskell Miso + GHC Wasm・モバイルファースト）
- **実装アーキテクチャ**:
  - **フロントエンド UI 全体も Haskell（Miso + GHC Wasm バックエンド）** で構築し、`src/common/` のドメイン型・差分ロジックをサーバとエンドツーエンドで共有する。
  - CodeMirror 6、IndexedDB、Service Worker 等のブラウザ固有 API のみを最小限の薄い JSFFI グルー層に局所化する。
- **対象ブラウザ**:
  - スマートフォンおよび PC のメジャーなモダンブラウザ（Chromium 系、Firefox 等）を対象とする。
  - Apple 系ブラウザ（Safari / iOS 系）の固有制約については制限事項としての対応を許容するが、モバイルファーストの観点から既知の制約は都度文書化する。
- **オフライン動作と PWA（M6）**:
  - オフライン時でも文書の閲覧・作成・編集（IndexedDB ドラフト保持）が可能であり、オンライン復帰時にサーバと安全に同期できること。
  - PWA（Service Worker + Web App Manifest）としてホーム画面へインストール可能とし、Wasm バイナリ等の静的アセットをキャッシュして 2 回目以降の起動を高速化する。

### 3-3. 性能・規模・国際化
- **想定文書規模**: 1 文書あたり最大 **数 MB 程度** のテキスト編集・保存・差分計算を実用速度で扱えること（極端に巨大なファイル向けの計算量制限は [backlog.md](./project/backlog.md) で管理）。
- **UI 言語**: 日本語を優先とし、将来的に多言語化（日英切替等）しやすいよう UI 文言をロジックから分離する設計とする。
