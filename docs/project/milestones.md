# マイルストーン定義

本ドキュメントは、プロジェクト全体の開発計画と各マイルストーンのスコープ・完了条件を定義します。
進捗と現在地は [../PROJECT.md](../PROJECT.md) を参照してください。
マイルストーンの追加や変更は Antigravity スキル `add-milestone` を通じて行います。

---

## M0: プロジェクト骨格と開発基盤の整備
- **目的**: 開発・テスト・検証を迅速かつ安全に行うためのプロジェクト構造とビルド・CI 基盤を整える。
- **作業項目**:
  - リポジトリ構成の初期化 (`src/{common,server,client,extension-api,extensions}/`, `scripts/`, `docker/`)
  - Haskell パッケージ構成 (Cabal / Stack) の設定
  - Docker 開発環境および自動化スクリプト (`scripts/check.sh`, `scripts/build.sh`, `scripts/test.sh`, `scripts/lint.sh`) の整備
  - OpenAPI 仕様の雛形作成 (`docs/api/openapi.yaml`)
- **完了条件**: `scripts/check.sh` がエラーなく実行でき、空のテスト・Lint がパスすること。

---

## M1: MVP サーバ (文書 CRUD + ローカル動作確認)
- **目的**: 文書の作成・読み取り・更新・削除を行う RESTful API サーバを構築し、データ永続化の基盤を作る。
- **作業項目**:
  - Warp / Servant 等による HTTP サーバ基盤の実装
  - SQLite による文書ストレージの実装
  - 文書 CRUD エンドポイント (`/api/documents`) の実装
  - 単体テストおよび統合テストの作成
- **完了条件**: REST API 経由で文書の CRUD 操作が正常に行え、SQLite に永続化されること。

---

## M2: MVP クライアント (最小エディタ UI)
- **目的**: ブラウザ上で動作するテキストエディタ UI を構築し、M1 サーバと接続して文書を編集・保存できるようにする。
- **作業項目**:
  - Haskell (Miso 等) または Wasm によるクライアント骨格の実装
  - エディタコンポーネント (CodeMirror 等の統合) の構築
  - 文書一覧表示・新規作成・編集・保存機能の実装
  - M1 サーバとの REST API 疎通
- **完了条件**: ブラウザ上で文書を入力・編集し、サーバへ保存および一覧の再読み込みができること。

---

## M3: 認証・ユーザ管理
- **目的**: 複数ユーザーが個別の文書空間を安全に扱えるよう、ユーザー登録・認証機能を実装する。
- **作業項目**:
  - ユーザー登録・ログイン・ログアウト API の実装
  - セッション管理および認証ミドルウェアの実装
  - 文書の所有者制御 (本人の文書のみアクセス可能にする)
- **完了条件**: 別々のユーザーアカウントでログインし、互いの文書が不可視・分離されていること。

---

## M4: 差分管理 Phase 1 (リビジョン履歴)
- **目的**: 文書の編集履歴を差分 (unified diff) として保持し、過去のリビジョンへの復元を可能にする。
- **作業項目**:
  - 編集保存時の diff 生成ロジックの実装
  - リビジョン履歴テーブルおよび取得 API の実装
  - 過去リビジョンの閲覧・特定版へのロールバック機能
- **完了条件**: 文書更新ごとにリビジョンが記録され、任意のリビジョンの内容を復元できること。

---

## M5: Haskell 拡張機構 (MVP)
- **目的**: Haskell で記述された拡張機能をクライアント側でロードし、エディタの挙動をカスタマイズできるようにする。
- **作業項目**:
  - 拡張用 API インターフェースの定義 (Haddock ドキュメント付き)
  - サンドボックス環境 (Web Worker 等) での拡張ロード・実行基盤
  - サンプル拡張 (文字列変換や書式整形など) の作成と動作検証
- **完了条件**: サンプル拡張をエディタに読み込ませ、エディタ内のテキストに対して拡張コマンドを実行できること。

---

## M6: PWA / オフライン対応
- **目的**: ネットワーク切断時でも文書編集を継続でき、再接続時にサーバと同期できるようにする。
- **作業項目**:
  - Service Worker と Web App Manifest の導入 (PWA 化)
  - IndexedDB 等を利用したローカルドラフト保存
  - オンライン復帰時の自動同期ロジック
- **完了条件**: オフライン状態で文書を編集・保存し、オンライン復旧後にサーバ側へ変更が同期されること。

---

## M7: 差分管理 Phase 2 (リビジョン比較とマージ)
- **目的**: 任意のリビジョン間の差分可視化、および同時編集時の 3-way マージや競合解決 UI を提供する。
- **作業項目**:
  - 任意 2 リビジョン間の diff 計算・UI 表示
  - 3-way マージアルゴリズムの実装
  - 競合発生時の手動解決 UI
- **完了条件**: 競合を含む同時更新が発生した際、競合マーカーが表示され、ユーザーが解決してマージ保存できること。
