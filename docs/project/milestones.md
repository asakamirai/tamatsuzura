# マイルストーン定義

本ドキュメントは、TamaTsuzura 全体の開発計画と各マイルストーンのスコープ・完了条件を定義します。
進捗と現在地は [../PROJECT.md](../PROJECT.md) を参照してください。
マイルストーンの追加や変更は Antigravity スキル `add-milestone` を通じて行います。

---

## M0: プロジェクト骨格と開発基盤の整備
- **目的**: 開発・テスト・検証を迅速かつ安全に行うための要件確定・プロジェクト構造・ビルド（サーバ + Wasm）・CI 基盤を整える。
- **作業項目**:
  - 要件定義の確定 (`docs/REQUIREMENTS.md` および関連設計書の同期)
  - リポジトリ構成の初期化 (`src/{common,server,client,extension-api,extensions}/`, `scripts/`, `docker/`)
  - Haskell パッケージ構成（サーバ/共通向け Stack・Cabal およびクライアント向け GHC Wasm / `wasm32-wasi-cabal` 方針）の設定
  - Docker 開発環境および自動化スクリプト (`scripts/check.sh`, `scripts/build.sh`, `scripts/test.sh`, `scripts/lint.sh`) の整備
  - OpenAPI 仕様の雛形作成 (`docs/api/openapi.yaml`)
- **完了条件**: `scripts/check.sh` がエラーなく実行でき、サーバ/共通パッケージの空テスト・Lint および Wasm クライアントの最小ビルド疎通がパスすること。

---

## M1: MVP サーバ (文書 CRUD + CGI / Warp 両対応)
- **目的**: 文書の作成・読み取り・更新・論理削除（ゴミ箱）を行う RESTful API サーバを構築し、レンタルサーバ等の CGI 環境と Warp スタンドアロン双方での動作基盤を作る。
- **作業項目**:
  - WAI / Servant による完全ステートレス HTTP アプリ基盤の実装
  - **CGI（`wai-extra` の `Network.Wai.Handler.CGI`）および Warp（`warp`）の両エントリポイント実装**
  - SQLite（WAL モード + `busy_timeout`）による文書ストレージと論理削除（ゴミ箱・復元・完全削除）・整理メタデータの実装
  - 文書 CRUD エンドポイント (`/api/documents` 等) の実装と OpenAPI 同期
  - 単体テストおよび CGI / Warp 双方の統合・疎通テストの作成
- **完了条件**: **CGI 環境および Warp スタンドアロン双方** で REST API 経由の文書 CRUD・論理削除が正常に動作し、SQLite に永続化されること。

---

## M2: MVP クライアント (モバイルファースト最小エディタ UI)
- **目的**: Haskell (Miso + GHC Wasm) と CodeMirror 6（薄い JSFFI）でスマートフォン優先のテキストエディタ UI を構築し、M1 サーバと接続して日常執筆できるようにする。
- **作業項目**:
  - Miso + GHC Wasm クライアント骨格と最小 JSFFI グルーの実装
  - CodeMirror 6 統合と**モバイルファースト**のレスポンシブ UI 構築（検索・置換、Markdown プレビュー、日本語優先の文言分離）
  - 文書一覧・整理（フィルタ/タグ等）・新規作成・編集・明示的保存・ゴミ箱・Markdown/テキストのエクスポート/インポート実装
  - 編集中未保存ドラフトの IndexedDB 自動退避
  - M1 サーバとの REST API 疎通
- **完了条件**: スマートフォンおよび PC のモダンブラウザで文書を入力・編集・プレビュー・明示的保存・ゴミ箱移動/復元・エクスポート/インポートでき、未保存ドラフト退避および再読み込み後の復元が正常に動作すること。

---

## M3: 認証・ユーザ管理
- **目的**: 複数ユーザーが個別の文書空間を安全に扱えるよう、CGI 完全互換のユーザー登録・認証機能を実装する。
- **作業項目**:
  - ブラウザからのユーザー新規登録（Sign up）・ログイン・ログアウト API および UI の実装
  - SQLite 永続化 Cookie セッション（インメモリ状態非依存）と安全なパスワードハッシュの実装
  - 将来のクローズド運用・登録制限に向けた設定分離の土台設計
  - 文書の所有者制御（本人の文書のみアクセス可能にする）
- **完了条件**: CGI / Warp 双方で別々のユーザーアカウントを作成・ログインでき、互いの文書が不可視・分離されていること。

---

## M4: 差分管理 Phase 1 (リビジョン履歴)
- **目的**: 明示的保存ごとの編集履歴を差分 (unified diff) として追記型で保持し、過去のリビジョン閲覧・復元を可能にする。
- **作業項目**:
  - `src/common/` での純粋な unified diff 生成・適用ロジックの実装（`hspec` + `QuickCheck`）
  - リビジョン履歴テーブルおよび取得・復元 API の実装
  - 過去リビジョンの閲覧・特定版へのロールバック UI（モバイル対応）
- **完了条件**: 明示的保存ごとにリビジョンが記録され、任意のリビジョンの内容を閲覧・復元できること。

---

## M5: Haskell 拡張機構 (MVP: 同梱拡張)
- **目的**: `src/extension-api/` を通じて、同梱・ビルド時組み込みの Haskell 拡張機能をクライアント側で有効化・実行できるようにする。
- **作業項目**:
  - 拡張用公開インターフェース (`src/extension-api/`) の定義と Haddock ドキュメント整備（将来の外部 `.wasm` / Web Worker 分離を見据えた疎結合設計）
  - Miso クライアントへの同梱拡張レジストリ・有効化/設定 UI・コマンド実行基盤の実装
  - サンプル拡張（文字列変換・Markdown 書式整形など）の作成と動作検証
- **完了条件**: 同梱サンプル拡張を UI から有効化し、エディタ内のテキストに対して拡張コマンドを実行できること。

---

## M6: PWA / オフライン対応
- **目的**: ネットワーク切断時でも文書編集を継続でき、再接続時にサーバと同期できるモバイル向け PWA 体験を完成させる。
- **作業項目**:
  - Service Worker と Web App Manifest の導入（PWA インストール対応、Wasm バイナリ等のキャッシュによる高速起動）
  - IndexedDB を利用したオフライン文書キャッシュ・未同期保存キューの整備
  - オンライン復帰時の自動同期ロジックと同期状態インジケータ（`parent_revision_id` 不一致などの競合検出時はサーバ側を上書きせず、ローカル未同期ドラフトを安全に退避・通知する。3-way マージ解決 UI は M7 で提供）
- **完了条件**: オフライン状態で文書を編集・保存し、オンライン復旧後にサーバ側へ変更が安全に同期され、競合時もデータ消失せず退避・通知されること。

---

## M7: 差分管理 Phase 2 (リビジョン比較とマージ)
- **目的**: 任意のリビジョン間の差分可視化、およびオフライン/同時編集時の 3-way マージ・競合解決 UI を提供する。
- **作業項目**:
  - 任意 2 リビジョン間の diff 計算・モバイル対応比較 UI
  - `src/common/` での純粋な 3-way マージアルゴリズムの実装（`hspec` + `QuickCheck`）
  - 競合発生時の手動解決 UI
- **完了条件**: 競合を含む同時更新が発生した際、競合箇所が表示され、ユーザーが解決してマージ保存できること。
