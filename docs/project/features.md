# 機能設計方針

本ドキュメントは、エディタのコア機能（文書管理、差分管理、拡張機構、オフライン同期）の詳細設計方針をまとめます。

---

## 1. 文書管理 (Document Management)
- **識別子**: 文書ごとに一意な ID (UUID または整数 ID) を付与。
- **メタデータ**: タイトル、作成日時、更新日時、所有者 ID。
- **本文データ**: UTF-8 テキストデータ。

---

## 2. 差分・リビジョン管理 (Revision & Diff)
- **リビジョン構造**:
  - 文書が保存されるたびに新しいリビジョンレコードを生成。
  - 親リビジョン ID (`parent_revision_id`)、変更差分 (`diff`)、コンテンツハッシュ (`content_hash`)、タイムスタンプを保持。
- **差分生成**:
  - 純粋な unified diff 形式で差分を算出し、効率的に保存。
- **復元とマージ**:
  - 過去リビジョンへのロールバック時は、diff を適用して過去スナップショットを再構成。
  - 同時編集競合時は、3-way マージアルゴリズムにより共通祖先リビジョンからの変更を合成。

---

## 3. Haskell 拡張機構 (Extension Mechanism)
- **ロード機構**:
  - 拡張は WebAssembly (.wasm) または JavaScript にコンパイルされた Haskell バイナリ。
  - ブラウザの Web Worker 内でロード・実行。
- **API スコープ**:
  - 初期スコープ: エディタバッファの読み取り、テキスト置換、カスタムコマンドの登録。
  - 将来スコープ: カーソル位置・選択範囲の取得、ショートカットキーバインド、サイドバー UI 連携。

---

## 4. オフライン動作と同期 (Offline & Sync)
- **ローカルバッファリング**:
  - IndexedDB に未同期の編集履歴や文書キャッシュを保持。
- **同期プロトコル**:
  - ネットワーク接続復帰を検知した時点で、ローカルの変更をサーバへ送信。
  - サーバ側で競合が検出された場合は、競合解決フローへ誘導する。
