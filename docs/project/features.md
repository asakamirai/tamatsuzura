# 機能設計方針

本ドキュメントは、TamaTsuzura のコア機能（文書管理、認証、差分管理、拡張機構、オフライン同期）の設計方針をまとめます。

---

## 1. 文書管理 (Document Management)
- **識別子**: 文書ごとに一意な ID（UUID 等、URL セーフな ASCII 識別子）を付与。
- **メタデータ**: タイトル（未入力/空文字許容）、フォーマット種別（`markdown` / `plain_text`、既定 `markdown`）、整理用メタデータ（タグ集合および論理フォルダ階層）、作成日時、更新日時、所有者 ID（M3〜）、削除日時（論理削除フラグ）。
- **本文データ**: UTF-8 テキストデータ（Markdown / プレーンテキスト、1 文書あたり最大 5 MiB を上限とする）。
- **論理削除（ゴミ箱）**:
  - 削除操作は `deleted_at` を設定する論理削除とし、ゴミ箱一覧からの復元および完全削除をサポートする。
- **入出力・表示**:
  - Markdown プレビュー表示（モバイル画面でも編集/プレビューを容易に切替可能）。
  - Markdown / プレーンテキスト形式のエクスポート（ダウンロード）およびインポート（ファイル読込）。

---

## 2. 認証・ユーザ管理 (Auth & Users)
- **初期登録フロー（M3）**: ブラウザからのオープン新規登録（Sign up）、ログイン、ログアウトを提供し、所有者ごとの文書分離を行う。
- **CGI 互換セッション**:
  - セッション ID を `HttpOnly` / `SameSite=Lax`（HTTPS 運用時は `Secure` 付与）Cookie で保持し、セッション実体は SQLite テーブルに永続化する（インメモリキャッシュ非依存）。状態変更 API には適切な CSRF 対策（`SameSite` + Origin 検証または CSRF トークン）を施す。
  - パスワードは安全なハッシュ関数（Argon2 / scrypt 等）で保存する。
- **将来の登録制限**: セルフホスト運用でのクローズド化（新規登録無効化フラグ・招待制・CLI ユーザー作成）を後付けしやすいよう、登録許可判定を設定層に分離する（[backlog.md](./backlog.md)）。

---

## 3. 保存モデルと差分・リビジョン管理 (Save, Revision & Diff)
- **明示的保存によるリビジョン確定**:
  - 編集中ドラフトは IndexedDB へ自動退避し、明示的保存（`Ctrl+S` / Save ボタン）時のみサーバへ送信して新しいリビジョンを生成する。
- **リビジョン構造**:
  - 親リビジョン ID (`parent_revision_id`)、変更差分 (`diff`)、コンテンツハッシュ (`content_hash`)、タイムスタンプを保持する。
- **差分生成**:
  - `src/common/` の純粋関数として unified diff 形式で差分を算出し、効率的に保存する。
- **復元とマージ**:
  - 過去リビジョンへのロールバック時は、diff を適用して過去スナップショットを再構成する（M4）。
  - 同時編集・オフライン同期競合時は、3-way マージアルゴリズムにより共通祖先リビジョンからの変更を合成し、競合箇所を手動解決 UI で提示する（M7）。

---

## 4. Haskell 拡張機構 (Extension Mechanism)
- **初期ロード方式（M5: 同梱・ビルド時組み込み）**:
  - `src/extension-api/` のインターフェースに準拠した Haskell 拡張モジュール群をクライアント Wasm ビルド時に同梱し、UI 設定から有効化・実行できるようにする。
- **API スコープ**:
  - 初期スコープ: エディタバッファの読み取り、テキスト置換、カスタムコマンドの登録・実行。
  - 将来スコープ: カーソル位置・選択範囲の取得、キーバインドカスタマイズ、サイドバー UI 連携、および外部ビルド `.wasm` の動的ロード＋Web Worker 分離実行（[backlog.md](./backlog.md)）。

---

## 5. オフライン動作と同期 (Offline & Sync)
- **ローカルバッファリング**:
  - IndexedDB に未保存ドラフト、未同期の保存キュー、および閲覧用文書キャッシュを保持する。
- **PWA キャッシュ**:
  - Service Worker によりアプリシェルおよび GHC Wasm バイナリをキャッシュし、オフライン起動とモバイルでの高速再起動を実現する。
- **同期プロトコル**:
  - ネットワーク復帰時に未同期の変更をサーバへ送信する。
  - 親リビジョンの不一致（競合）が検出された場合は、データ消失を防ぎつつ競合解決フローへ誘導する。
