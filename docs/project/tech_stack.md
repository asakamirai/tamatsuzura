# 技術スタック選定方針

本ドキュメントは、本システムで採用する技術スタック、選定理由、および開発前提を定義します。

---

## 1. コア技術一覧

| レイヤー | 技術 / ツール | 選定理由・目的 |
| --- | --- | --- |
| **主要言語** | Haskell (GHC 9.x 系列) | 強力な静的型付け、純粋関数型モデルによる不変性、バグの未然防止 |
| **ビルドツール** | Stack / Cabal | 再現性の高いパッケージ管理と依存関係の固定 |
| **バックエンド** | Warp / Servant | 軽量・高速な HTTP サーバおよび型安全な Web API 定義 |
| **データベース** | SQLite (Direct-sqlite 等) | ポータブル、セットアップ容易、信頼性の高い ACID トランザクション |
| **フロントエンド** | Miso (Haskell) または TypeScript/Wasm | 型安全な UI 構築と Wasm/JS コンパイルの適合性 |
| **エディタコア** | CodeMirror 6 (または同等の軽量エディタ) | 拡張性、モバイル対応、豊富なエコシステム |
| **コンテナ環境** | Docker / Docker Compose | 開発者およびエージェントの環境差異をなくす統一実行基盤 |
| **AI エージェント** | Antigravity (AGY) | ルール、ネイティブスキル、サンドボックス実行による高品質な開発自動化 |

---

## 2. 開発・実行方針

- `scripts/` 配下のラッパースクリプト (`scripts/check.sh` 等) を統一窓口とし、ホスト側からは単一コマンドでビルド・テスト・Lint を完結できるようにします。
- ホストに `stack` / `hlint` が導入されている環境ではホスト側ツールを優先して高速かつ Antigravity 標準サンドボックス内で実行し、未導入環境やクリーンな再現性検証時 (`USE_DOCKER=1`) には Docker コンテナへフォールバックします。
