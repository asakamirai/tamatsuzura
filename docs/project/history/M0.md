# M0 完了記録: プロジェクト骨格と開発基盤の整備

- **完了日**: 2026-11-20
- **対象マイルストーン**: M0（[milestones.md](../milestones.md)）

## 達成内容

1. **Phase 0: 要件定義の確定** (`37f0fc8`)
   - 個人〜少人数セルフホスト向けのモバイルファースト Markdown / プレーンテキストエディタとして要件を確定（[REQUIREMENTS.md](../../REQUIREMENTS.md)）。
   - サーバは CGI（`wai-extra` の `Network.Wai.Handler.CGI`）最優先＋Warp 両対応、クライアントは Haskell Miso + GHC Wasm（`wasm32-wasi-cabal`）＋薄い JSFFI（CodeMirror 6 / IndexedDB / Service Worker）、拡張機構は M5 同梱拡張から開始する設計を全設計書へ同期。
   - クローズド登録制限・外部 `.wasm` 動的ロード＋Web Worker 分離・多言語化（i18n）等の意図的先送り課題を [backlog.md](../backlog.md) へ集約。
2. **Phase 1: リポジトリ構成とビルドツールの初期設定** (`4497f7e`)
   - 5 パッケージ（`tamatsuzura-common`, `tamatsuzura-extension-api`, `tamatsuzura-extensions`, `tamatsuzura-server`, `tamatsuzura-client`）を Cabal 3.0 の単一 `.cabal` 定義で構築し、`stack.yaml`（LTS 24.67 / GHC 9.10.3）・`cabal.project`・`cabal.project.wasm`・`.hlint.yaml` を整備。
   - `tamatsuzura-client` を内部サブライブラリ `client-core` と結線層 `ExtensionRegistry` に分離し、アーキテクチャ境界をコンパイル時強制。
   - `tamatsuzura-server` に共通 WAI `/api/health`（[docs/api/openapi.yaml](../../api/openapi.yaml) 雛形準拠）と Warp / CGI 両バイナリを実装し、CGI/1.1 実バイナリ単体疎通を確認。
3. **Phase 2: Docker 開発環境および Wasm 最小ビルドの疎通確認** (`38e6027`)
   - `docker/Dockerfile` に `ghc-wasm-meta`（`FLAVOUR=9.10`）・HLint 3.8・Stack・Node.js/pnpm を統合し、`docker/docker-compose.yml` に `STACK_WORK=.stack-work-docker` と `ghc-wasm-cabal` ボリュームを設定。
   - `scripts/build-wasm.sh` を新設し、`scripts/build.sh` と連携（`tamatsuzura-client.wasm` 1.4MB / `\0asm` 生成および `USE_DOCKER=1` での `build` / `test` / `lint` 全通過を確認）。
4. **Phase 3: 自動検証・CI スクリプト (`scripts/check.sh`) の稼働確認**
   - `scripts/check.sh` のログ見出し整形と全実行モード（デフォルトハイブリッド、`USE_DOCKER=1` フル Docker、`SKIP_WASM=1` ネイティブ限定）の連続通過を実機検証。
   - [AGENTS.md](../../../AGENTS.md) のディレクトリ構造を確定版へ更新し、M1 の Phase 分割を [PROJECT.md](../../PROJECT.md) へ、GitHub Actions CI 整備の先送りを [backlog.md](../backlog.md) へ反映。
