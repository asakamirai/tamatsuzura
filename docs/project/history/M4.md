# M4 完了記録: 差分管理 Phase 1 (リビジョン履歴)

- **完了日**: 2026-11-22
- **対象マイルストーン**: M4（[milestones.md](../milestones.md)）

## 達成内容

1. **Phase 1: 純粋な unified diff 生成・適用ロジックとリビジョンドメイン型・OpenAPI 仕様拡張** (`10c2e58`)
   - `TamaTsuzura.Common.Diff` に共通前後トリミング＋Myers O(ND) ベースの unified diff 生成・パース・厳格適用・反転（`applyUnifiedDiffReverse`）および末尾改行なし（`\ No newline at end of file`）完全可逆処理を実装し、`hspec` + `QuickCheck` でラウンドトリップ不変条件を検証。
   - `TamaTsuzura.Common.Revision` に `RevisionId` / `ContentHash`（SHA-256 64 文字小文字 hex）/ `RevisionSummary` / `RevisionDetail` / `RevisionListResponse` / `RestoreRevisionRequest` と `revisionContentCanonicalText` を実装。
   - [docs/api/openapi.yaml](../../api/openapi.yaml) を v0.4.0 へ同期し、`/api/documents/{id}/revisions`・`/api/documents/{id}/revisions/{revision}`・`/api/documents/{id}/revisions/{revision}/restore` および `base_revision` 楽観的排他仕様を定義。
2. **Phase 2: SQLite リビジョン履歴テーブルおよび履歴取得・復元 API の実装（CGI / Warp 両検証）** (`5107378`)
   - SQLite スキーマ v4 へ追記型 `document_revisions` テーブルを追加し、文書作成・更新時の差分記録と内容ハッシュ同一時の重複リビジョン抑止、および差分チェーンからの過去スナップショット再構成を実装。
   - 履歴一覧取得（降順・`limit`/`offset` ページネーション）・特定リビジョン詳細取得（再構成本文 + unified diff）・過去版への追記型ロールバック復元 API（`base_revision` 楽観的排他・ゴミ箱内文書 409 拒否・所有者分離）を実装し、Warp / CGI 双方で統合テストを検証。
3. **Phase 3: Miso クライアントへの過去リビジョン閲覧・復元 UI（モバイル対応）統合と疎通検証**
   - `TamaTsuzura.Client.Api` に `listDocumentRevisions` / `getDocumentRevision` / `restoreDocumentRevision` と純粋なリクエストビルダーを追加。
   - `TamaTsuzura.Client.App`・`View`・`I18n`・`styles.css` にモバイルファースト編集履歴パネル（ツールバー **履歴** トグル、ステータスバー現在リビジョン `r<N>` 表示、50 件超対応の **さらに読み込む** ページネーション、**本文** / **差分** タブ切替、追加/削除/コンテキスト/末尾改行なしマーカーの unified diff ハイライト、確認モーダル付き過去版復元、ゴミ箱内閲覧専用案内）を統合。
   - CodeMirror 6 DOM を破棄せず履歴パネルと切り替える構造、世代番号によるパネル閉鎖・文書切替後の陳腐応答破棄、`restoringRevisionDoc` による復元中レース防止と保存・削除との相互排他、および開中履歴の保存時自動リフレッシュを実装。
   - クライアント単体/MVU テストおよび手動検証手順書（[MANUAL_TESTS.md](../../MANUAL_TESTS.md) MT-6）を同期更新。
