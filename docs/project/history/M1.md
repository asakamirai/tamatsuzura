# M1 完了記録: MVP サーバ (文書 CRUD + CGI / Warp 両対応)

- **完了日**: 2026-11-20
- **対象マイルストーン**: M1（[milestones.md](../milestones.md)）

## 達成内容

1. **Phase 1: 共通ドメイン型と OpenAPI 仕様の定義** (`cf4e408`)
   - `tamatsuzura-common` に完全純粋な文書ドメイン型（`DocumentId`, `DocumentTitle`, `DocumentBody`, `DocumentFormat`, `Tag`, `TagSet`, `FolderPath`, `DocumentSummary`, `Document`）、一覧クエリ/CRUD DTO（`DocumentListQuery`, `CreateDocumentRequest`, `UpdateDocumentRequest`, `DocumentListResponse`, `TagListResponse`, `FolderListResponse`）、構造化エラー型（`ApiError`, `ApiErrorCode`, `ValidationError`）を実装。
   - [docs/api/openapi.yaml](../../api/openapi.yaml) を M1 全エンドポイント・制約・エラーレスポンス定義へ同期更新し、`hspec` + `QuickCheck` で単体・プロパティテストを整備。
2. **Phase 2: SQLite 永続化層の実装** (`4784d87`)
   - `TamaTsuzura.Server.Storage` / `Storage.Schema` / `Storage.Types` を実装。`OsPath` ベースで親ディレクトリ自動作成・`PRAGMA busy_timeout`・WAL モード・`foreign_keys = ON`・`PRAGMA user_version` による冪等スキーマ初期化（ダブルチェックロッキング）を構築。
   - 書き込み用 `BEGIN IMMEDIATE` / 読み取りスナップショット用 `BEGIN` トランザクション、文書 CRUD、冪等な論理削除/復元・完全削除（`ON DELETE CASCADE`）、タグ/フォルダ/サブフォルダ前方一致/検索/ページネーションを実装し、ロック競合・ロールバック・破損データ検出を含む単体テストを整備。
3. **Phase 3: WAI / Servant REST API 実装および Warp / CGI 統合・疎通テスト**
   - `TamaTsuzura.Server.Config` で `TAMATSUZURA_DB_PATH` / `TAMATSUZURA_DB_BUSY_TIMEOUT_MS` / `PORT` / `SCRIPT_NAME` および Warp CLI 引数（`--port`, `--db-path`, `--busy-timeout-ms`）の厳格な検証・解決を実装。
   - `TamaTsuzura.Server.Api` に [docs/api/openapi.yaml](../../api/openapi.yaml) と 1 対 1 対応する Servant API 型、正確な `field` 名付きクエリ/パス検証、JSON `ErrorFormatters` を実装。
   - `TamaTsuzura.Server.App` にリクエスト単位 `withStorage` による完全ステートレスハンドラ、16 MiB 生リクエストボディ上限ガード、405/415 等を含む JSON `ApiError` 正規化ミドルウェア、`SCRIPT_NAME=/api` マウント差分吸収ミドルウェアを実装し、`WarpMain.hs` / `CgiMain.hs` 双方へ統合。
   - `ApiSpec`（WAI セッションテスト）、`IntegrationSpec`（実 TCP Warp サーバ + `Network.Wai.Handler.CGI.runGeneric` CGI/1.1 統合テスト）、および実バイナリ（`tamatsuzura-server` / `tamatsuzura-cgi`）の疎通確認・手動検証手順（[MANUAL_TESTS.md](../../MANUAL_TESTS.md) MT-2）を整備。
